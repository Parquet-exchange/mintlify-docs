The Parquet TypeScript SDK is a thin wrapper around the on-chain programs that make up the protocol. It exposes **six program clients** — `PoolClient`, `PerpClient`, `OracleClient`, `PriceFeedClient`, `FeeDistributorClient`, and `StakingClient` — plus an `IndexerClient` (HTTP reads), a `ParquetEventEmitter` (log subscriptions), account decoders, and `utils/priceMath` helpers. Every instruction-builder method ends in `Ix` and returns an Anchor `TransactionInstruction`. The SDK never sends transactions on your behalf — you compose, sign, and submit. That keeps the surface predictable: you can batch instructions, attach compute-budget directives, route through your own priority-fee logic, or hand off to a wallet adapter without fighting an opinionated client.

| Export | Kind | Purpose |
|--------|------|---------|
| `PoolClient` | program client | LP deposits/withdrawals, fee accrual, payout-queue cranks, insurance fund |
| `PerpClient` | program client | Markets, positions, orders, liquidations, referrals, `getProtocolConfig` |
| `OracleClient` | program client | Authority-only market-oracle registration + feed updates |
| `PriceFeedClient` | program client | `price-feed` program admin (`setAdminIx`) — admin-rotation only |
| `FeeDistributorClient` | program client | Operator-side fee routing and split config |
| `StakingClient` | program client | Stake/unstake and reward distribution across emission pools |
| `IndexerClient` | HTTP client | Prices, positions, OHLCV, queue state, `/market-hours` |
| `ParquetEventEmitter` | event helper | Subscribe to on-chain program logs |
| account decoders | functions | `decodePosition`, `decodeMarketState`, `decodePoolState`, … (`./decode`) |
| `utils/priceMath` | functions | The canonical price normalizer (prices are 1e9-scaled — see below) and PnL/fee/health math |

<Tip>
  All on-chain prices are scaled by **1e9** (so a $100.00 price is stored as
  `100_000_000_000n`). Use `utils/priceMath` (`formatPrice`, `calcPnl`,
  `calcFee`, `calcHealth`) rather than dividing by hand — it resolves the
  mantissa-format footgun the [API page](/network/api) warns about and keeps
  your off-chain math in the same units as the programs.
</Tip>

<Note>
Parquet trades 24/7. Every state-changing instruction reads the oracle via `oracle_adapter`, and under the pyth-hybrid oracle that read succeeds in every session (Pyth primary during RTH; the relayer-written `PriceFeed` PDA carrying the off-hours reference). The indexer's [`GET /market-hours`](/network/api#get-market-hours) still tells you which risk-parameter column applies — off-hours, the per-market OI cap drops from $5M to $500K and the ADL tail-backstop is armed (the leverage tiers themselves are now identical in every session) — but it is no longer a gate against submitting. `PriceStale (6000)` outside RTH should be treated as a transient pricing incident, not an expected market state.
</Note>

## Install and provider setup

Install from npm:

```bash
npm install @parqxchange/sdk
# or: yarn add @parqxchange/sdk / pnpm add @parqxchange/sdk
```

Each client takes an Anchor `Program` in its constructor, so you set up a provider once and instantiate clients per program.

```typescript
import { AnchorProvider, Program, Wallet } from "@coral-xyz/anchor";
import { Connection, Keypair } from "@solana/web3.js";
import {
  PoolClient,
  PerpClient,
  OracleClient,
  PriceFeedClient,
  FeeDistributorClient,
  StakingClient,
  IndexerClient,
} from "@parqxchange/sdk";
import poolIdl from "@parqxchange/sdk/idl/pool_program.json";
import perpIdl from "@parqxchange/sdk/idl/perp_engine.json";
import oracleIdl from "@parqxchange/sdk/idl/oracle_adapter.json";
import priceFeedIdl from "@parqxchange/sdk/idl/price_feed.json";
import feeIdl from "@parqxchange/sdk/idl/fee_distributor.json";
import stakingIdl from "@parqxchange/sdk/idl/staking.json";

const connection = new Connection(process.env.RPC_URL!, "confirmed");
const wallet = new Wallet(Keypair.fromSecretKey(/* ... */));
const provider = new AnchorProvider(connection, wallet, { commitment: "confirmed" });

const pool = new PoolClient(new Program(poolIdl, provider));
const perp = new PerpClient(new Program(perpIdl, provider));
const oracle = new OracleClient(new Program(oracleIdl, provider));
const priceFeed = new PriceFeedClient(new Program(priceFeedIdl, provider));
const fees = new FeeDistributorClient(new Program(feeIdl, provider));
const staking = new StakingClient(new Program(stakingIdl, provider));

// HTTP reads (prices, positions, OHLCV, queue state) — no Anchor Program needed
// Optional second arg: timeout ms (default 15_000). Uses AbortSignal.timeout (Node 18+).
const indexer = new IndexerClient("https://api.parquet.exchange");
```

Program IDs live in [/network/contracts](/network/contracts). The program IDLs ship inside the package; import them from `@parqxchange/sdk/idl/*`.

## Package entry points (`exports`)

The published package exposes three entry paths (Node 18+; bundlers must honor `package.json` `"exports"`):

| Path | Import | Use when |
|------|--------|----------|
| Full barrel | `@parqxchange/sdk` | All program clients, account decoders, events, indexer, trading-key ix builders. |
| Minimal | `@parqxchange/sdk/minimal` | `PerpClient`, `openPosition` / `closePosition` / `updateMargin`, `getMarketOracleFeeds` — smaller module graph (no full decode barrel). |
| Node | `@parqxchange/sdk/node` | `loadTradingKeypair` only — **never** import from browser apps (filesystem). |

**Migration:** `loadTradingKeypair` moved off the default barrel — use `import { loadTradingKeypair } from "@parqxchange/sdk/node"`.

**Sharp corners:** Before production, read the integrator matrix below.

## Sharp corners (integrator checklist)

| F-id | What goes wrong | What to do |
|------|-----------------|------------|
| **F-3** | Trading-key register/revoke hits `.rpc()` when you expected unsigned prep. | Use `buildRegisterTradingKeyIx` / `buildRevokeTradingKeyIx` + your send path. |
| **F-4** | `loadTradingKeypair` drags `fs` into a web bundle. | `@parqxchange/sdk/node` only; never from the client bundle. |
| **F-5** | Missing or wrong oracle feed PDAs on open/close. | Use `resolveOpenPositionAccounts` / `resolveClosePositionAccounts` + `getMarketOracleFeeds` (dual-feed). See [OracleClient](#oracleclient) below. |
| **F-11** | `node:crypto` not resolved in the browser. | Decode on the server, or configure the bundler for `node:` imports. |
| **F-13** | Oracle feed cache keyed by RPC URL collides across clusters. | `clearMarketOracleFeedsCache()` on cluster switch; see minimal entry if you only need feeds + perp. |
| **F-19** | Marginal-length `MarketOracle` account. | SDK requires **158** bytes before tail fields; shorter data is rejected. |
| **F-20** | Winning close without queue PDAs on enqueue path. | Always pass `queueEntryPda` and `userClaimsPda` (see warning under [PerpClient](#perpclient)). |
| **F-21** | Untrusted program logs → `decodeAnchorEvent`. | Treat as untrusted: returns **`null`** if base64 is bad, payload too short, or inner decode fails — never assume non-null means “fully trusted.” |
| **F-25** | `acceptablePrice` / `minOutputUsdc` = `0n`. | No slippage guard — set explicit limits in prod. |

## PoolClient

`PoolClient` wraps the liquidity pool program — LP deposits, withdrawals, fee accrual, and the v4 payout-queue cranks.

| Method | Args (summary) | Returns | What it does |
|--------|----------------|---------|--------------|
| `initializePoolIx` | `authority`, pool config | `TransactionInstruction` | One-time pool init; sets fee splits, caps, queue parameters |
| `updatePoolConfigIx` | config patch | `TransactionInstruction` | Authority-only config update |
| `depositIx` | `lp`, `usdcAmount` | `TransactionInstruction` | Mints LP shares against a USDC deposit |
| `withdrawIx` | `lp`, `shareAmount` | `TransactionInstruction` | Burns shares and returns USDC pro-rata |
| `sweepFeesIx` | `caller` | `TransactionInstruction` | Pushes accumulated trading fees into the fee distributor |
| `accrueFeeIx` | `caller` | `TransactionInstruction` | Snapshots per-share fee index for LP accounting |
| `harvestIx` | `lp` | `TransactionInstruction` | v4 — drains an LP's mature queue claims back into available liquidity |
| `voidQueueClaimIx` | `claim`, `reason` | `TransactionInstruction` | v4 — cancels a stale or invalid payout-queue entry |
| `drainPhantomCreditIx` | `lp` | `TransactionInstruction` | v4 — clears residual credit dust after queue reconciliation |
| `initializeInsuranceFundIx` | `admin` | `TransactionInstruction` | Authority — one-time init of the insurance fund + its USDC vault |
| `reimbursePoolFromFundIx` | `amount` | `TransactionInstruction` | Authority — tops the pool back up from the insurance fund |
| `withdrawInsuranceIx` | `amount`, dest | `TransactionInstruction` | Authority — withdraws from the insurance vault |

The trailing three methods are the new v4 surface introduced by the LP payout queue redesign. Indexer keepers call them on a schedule; LP UIs surface `harvestIx` to end users so they can pull matured claims at will.

```typescript
import { Transaction } from "@solana/web3.js";

const ix = await pool.depositIx({
  lp: provider.wallet.publicKey,
  usdcAmount: 1_000_000_000n, // 1,000 USDC at 6 decimals
});

const tx = new Transaction().add(ix);
const sig = await provider.sendAndConfirm(tx);
console.log("deposit confirmed:", sig);
```

## PerpClient

`PerpClient` wraps the perp engine — markets, positions, orders, liquidations, and the on-chain referral system.

| Method | Args (summary) | Returns | What it does |
|--------|----------------|---------|--------------|
| `initializeMarketIx` | `marketId`, config | `TransactionInstruction` | Authority-only market init |
| `updateMarketConfigIx` | config patch | `TransactionInstruction` | Adjusts max leverage, fees, OI caps |
| `openPositionIx` | `accounts`, `args` (`sizeUsdc`, `walletCollateral`, `fromQueueAmount`, `side`, …), `primaryFeedAccount`, `secondaryFeedAccount` | `TransactionInstruction` | Opens a perp position; v4 splits collateral source |
| `closePositionIx` | `accounts`, `closeSize \| null`, `primaryFeedAccount`, `secondaryFeedAccount`, `minOutputUsdc?`, `queueEntryPda?`, `userClaimsPda?` | `TransactionInstruction` | Closes full or partial size; `null` closes the entire position. Pass the queue PDAs when closing a winner against a drawn-down pool |
| `updatePositionMarginIx` | `delta` | `TransactionInstruction` | Adds or removes margin from an existing position |
| `updateFundingRateIx` | `market` | `TransactionInstruction` | Keeper crank — recomputes funding from skew |
| `createOrderIx` | order params | `TransactionInstruction` | Posts a conditional/limit order on-chain |
| `cancelOrderIx` | `order` | `TransactionInstruction` | Cancels an outstanding order |
| `executeOrderIx` | `order` | `TransactionInstruction` | Keeper-only — fills a triggered order |
| `liquidateIx` | `position`, `liquidator` | `TransactionInstruction` | Permissionless liquidation when margin falls below maintenance |
| `configureReferralTiersIx` | tier table | `TransactionInstruction` | Authority — sets affiliate tier thresholds |
| `setReferralTierIx` | `referrer`, `tier` | `TransactionInstruction` | Authority — manually pins a referrer's tier |
| `createReferralCodeIx` | `referrer`, `code` | `TransactionInstruction` | Registers a referral code PDA |
| `setTraderReferralIx` | `trader`, `code` | `TransactionInstruction` | Binds a trader to a referrer at first use |
| `claimAffiliateRewardIx` | `referrer` | `TransactionInstruction` | Affiliate-facing — claims accrued referral rewards |
| `setPerSideReservedIx` | `market`, reserved | `TransactionInstruction` | Authority — sets the per-side reserved-liquidity figure on a market |
| `migrateMarketStateIx` | `market` | `TransactionInstruction` | Authority — one-shot `MarketState` schema migration |
| `migratePositionIx` | `position` | `TransactionInstruction` | Authority — one-shot `Position` schema migration |
| `getProtocolConfig` | — | `Promise<ProtocolConfig>` | **Read** (not an `Ix`) — fetches the decoded `ProtocolConfig` account |

<Warning>
  **v4 breaking change — `openPositionIx`.** The v4 perp engine splits position
  collateral into two sources: `walletCollateral` (transferred from the trader's
  USDC token account at open time) and `fromQueueAmount` (drawn from an LP
  payout-queue credit the trader already holds). v3 took a single
  `collateralUsdc`; that field no longer exists. Front-ends that always pay from
  wallet pass `fromQueueAmount: 0n`. See [/developer/payout-queue](/developer/payout-queue)
  for the queue-drawn collateral semantics.
</Warning>

<Tip>
  `closePositionIx` supports partial closes via the `closeSize` parameter — pass
  a `bigint` for partial, or `null` to close the entire position. The full feature
  page lives at [/developer/partial-close](/developer/partial-close), including
  realized-PnL math and the per-market minimum size rules.
</Tip>

<Warning>
  **Closing a winner against a drawn-down pool.** When the close may realize a
  gain the pool can't pay in full, the on-chain handler routes it through the
  payout queue (`enqueue_winner`) — and that path needs two extra accounts. The
  contract decides at runtime, so callers should **always pre-derive and pass**
  `queueEntryPda` (`payoutQueueEntryPDA`) and `userClaimsPda`
  (`userQueueClaimsPDA`) as the 6th and 7th arguments. If you omit them, the SDK
  substitutes `SystemProgram.programId` placeholders and the enqueue path will
  fail. See [/developer/payout-queue](/developer/payout-queue).
</Warning>

```typescript
import { Transaction } from "@solana/web3.js";

// openPositionIx(accounts, args, primaryFeedAccount, secondaryFeedAccount).
// All args amounts are bigint in USDC 6-decimal base units (500 USDC = 500_000_000n).
// The accounts object is large (marketState, position, vaults, pool, oracle,
// engineAuth, marketOracle, userClaims, feeSettings, optional referral/affiliate,
// …). Rather than hand-deriving every PDA, call the resolver:
//   const { accounts } = resolveOpenPositionAccounts(
//     marketId, signer, nonce, usdcMint, primaryFeedAccount, programIds, tradingKeyPda);
// then spread it into the call. The literal below is shown for illustration only.
const ix = await perp.openPositionIx(
  {
    marketState: marketPda,
    position: positionPda,
    signer: provider.wallet.publicKey,
    // ...the remaining accounts resolveOpenPositionAccounts returns
    // (vaults, pool, oracle, engineAuth, marketOracle, userClaims, feeSettings, etc.)
  },
  {
    side: { long: {} },
    sizeUsdc: 2_000_000_000n,            // 2,000 USDC notional
    walletCollateral: 500_000_000n,      // 500 USDC paid from wallet
    fromQueueAmount: 0n,                 // none drawn from the payout queue
    acceptablePrice: 45_000_000_000n,    // slippage guard, 1e9-scaled price ($45.00); 0n = no check
    minOutputUsdc: 0n,                   // unused at open
    positionNonce: 0n,                   // position PDA nonce
    referralCode: new Array(32).fill(0), // 32 zero bytes = no referral
  },
  primaryFeedAccount,   // Pyth PriceUpdateV2 — primary during RTH
  secondaryFeedAccount, // PriceFeed PDA fallback — relayer-written off-hours reference
);

const tx = new Transaction().add(ix);
await provider.sendAndConfirm(tx);
```

## OracleClient

`OracleClient` exposes **two** instruction-builders, both authority-only:

| Method | Args (summary) | Returns | What it does |
|--------|----------------|---------|--------------|
| `registerMarketOracleIx` | `market`, feed config | `TransactionInstruction` | Authority-only — binds a market's `MarketOracle` to its primary/secondary feeds |
| `updateMarketOracleFeedsIx` | `market`, feed patch | `TransactionInstruction` | Authority-only — repoints the primary/secondary feeds (e.g. flips primary to a Pyth `PriceUpdateV2`) |

Price reads themselves happen via CPI from the perp engine and pool program at instruction time, not via SDK calls. If you need to inspect a current price off-chain, do **not** hand-decode byte offsets — use the SDK's dual-feed read path: `getMarketOracleFeeds(connection, marketId, oracleProgramId)` resolves the market's primary + secondary feed accounts, and `decodePythPriceUpdate(...)` / `decodeSwitchboardPriceFeed(...)` (all exported from `@parqxchange/sdk`) decode each account into a `{ price, confidence, timestamp }` triple matching the on-chain `validate_and_read_price` output. Prices come back 1e9-scaled — pass them through `utils/priceMath` (`formatPrice`) for display. These off-chain reads never participate in settlement.

## FeeDistributorClient

`FeeDistributorClient` is the operator-side surface for fee routing.

| Method | Args (summary) | Returns | What it does |
|--------|----------------|---------|--------------|
| `distributeFeesIx` | `caller` | `TransactionInstruction` | Splits the fee pool by configured percentages |
| `updateFeeSplitIx` | `stakerSplitBps`, `treasurySplitBps`, `referralSplitBps` | `TransactionInstruction` | Authority — sets the FeeDistributor's **3-way** split of the swept non-LP remainder (staker / treasury / referral). The LP cut is **not** set here — it's `lp_fee_bps` on each `MarketState` |
| `updateFeePoolAccountsIx` | account map | `TransactionInstruction` | Authority — repoints destination token accounts |
| `withdrawTreasuryIx` | `amount`, `dest` | `TransactionInstruction` | Authority — pulls from the treasury bucket |
| `disburseReferralIx` | `referrer` | `TransactionInstruction` | Internal — moves accrued amount into the referrer's claimable balance |

<Note>
  The affiliate-facing claim flow lives on `PerpClient.claimAffiliateRewardIx`,
  not here. `FeeDistributorClient` handles the operator/admin side: sweeping
  fees, adjusting splits, treasury withdrawal, and the underlying
  `disburseReferralIx` that feeds the claimable balance the affiliate later
  withdraws.
</Note>

## StakingClient

`StakingClient` covers stake/unstake and reward distribution across multiple emission pools.

| Method | Args (summary) | Returns | What it does |
|--------|----------------|---------|--------------|
| `stakeIx` | `staker`, `amount` | `TransactionInstruction` | Locks tokens into a staking pool |
| `unstakeIx` | `staker`, `amount` | `TransactionInstruction` | Withdraws stake subject to any cooldown |
| `claimRewardIx` | `staker`, `pool` | `TransactionInstruction` | Claims accrued rewards from one pool |
| `updateRewardIndexIx` | `pool` | `TransactionInstruction` | Crank — advances the per-share reward index |
| `initializeEmissionPoolIx` | pool config | `TransactionInstruction` | Authority — creates an emission-schedule pool |
| `claimAndRestakeIx` | `staker` | `TransactionInstruction` | Atomic — claims LP-emission rewards and restakes into the protocol-token pool in one instruction |
| `reclaimUnallocatedIx` | `pool` | `TransactionInstruction` | Authority — pulls unemitted tokens back from a wound-down pool |

Each pool carries a `reward_source` discriminator. `BalanceBased` pools pay out of a deposited reward balance and stop when it runs dry; `EmissionSchedule` pools accrue at a fixed rate over a window and ignore the on-chain balance until claim time. `claimAndRestakeIx` is the headline ergonomics win for stakers — instead of claim → swap → stake across three transactions, an LP staker compounds emissions into the protocol-token pool atomically.

## Error handling

Anchor wraps every program error in `AnchorError` with a stable numeric `code` and a human-readable `name`. Catch and switch on `err.error.errorCode.number`:

```typescript
import { AnchorError } from "@coral-xyz/anchor";

try {
  await provider.sendAndConfirm(tx);
} catch (err) {
  if (err instanceof AnchorError) {
    const code = err.error.errorCode.number;
    console.error(`anchor error ${code}: ${err.error.errorCode.code}`);
    console.error(err.error.errorMessage);
  } else {
    throw err;
  }
}
```

Common codes you will see during normal SDK use:

All codes below are the **real on-chain `errorCode.number`** (Anchor 0.31 = Rust discriminant + 6000) — exactly what `err.error.errorCode.number` carries and what the SDK's `ParquetError` enum / `decodeError` match against.

| Code | Name | Origin | Cause |
|------|------|--------|-------|
| 7001 | `PriceStale` | perp_engine | The perp engine's own staleness guard tripped after reading the oracle (distinct from the oracle-adapter `6000` below — same name, different program + code) |
| 8005 | `OiCapExceeded` | perp_engine | Open interest cap for the side would be breached by this open/increase ($5M per market RTH; $500K per market off-hours) |
| 8006 | `BelowMinCollateral` | perp_engine | Position margin would fall below the $10 minimum after the operation |
| 6008 | `WrongAccountOwner` | fee_distributor | An account passed to the instruction is owned by a different program than expected |
| 6000 | `PriceStale` | oracle_adapter | Oracle price is older than the staleness threshold — pricing temporarily unavailable (transient WS dropout, relayer restart, or upstream feed gap) |
| 10005 | `ProtocolHalted` | perp_engine | Venue-wide halt (`HaltMode`) — opens and risk-increasing paths revert; decode via SDK `ParquetError.ProtocolHalted` / `decodeError` |
| 10006 | `InvalidHaltMode` | perp_engine | Admin set an invalid halt byte — `ParquetError.InvalidHaltMode` |

`8005` and `8006` are user-actionable — surface them as "market full" and "increase margin" respectively. Price-staleness shows up as **two distinct codes**: `7001` `PriceStale` from **perp_engine** (its own post-read guard) and `6000` `PriceStale` from **oracle_adapter** (the feed itself aged out) — same name, different programs, so match on both. Pre-2026-05-20 (RTH-only era) staleness was the canonical RTH-halt signal; post-24/7-unlock either should be surfaced as "pricing temporarily unavailable — try again in a few seconds" (transient WS dropouts or relayer restarts), and any extended occurrence is an incident, not a normal market state. `6008` is a wiring bug; if you see it in production it almost always means the client was pointed at the wrong program ID or a stale PDA cache. Cross-check the program IDs listed in [/network/contracts](/network/contracts).
